# SEO Backend Contract

This is an additive backend contract. Next.js does not consume these fields yet.
No SEO plugin is needed. No canonical URLs, robots directives, HTML head fragments,
or structured-data claims are generated by this backend. The frontend remains
responsible for canonical frontend-domain URLs, fallbacks, metadata rendering,
and the decision to index each public route.

## Editing

- Pages have an **SEO and sharing** meta box: optional title, description,
  sharing image, and sharing image alternative text. Supported frontend routes
  are About, Contact, Portfolio, Videos, and Legal. Other WordPress Pages can
  store SEO fields, but have no corresponding frontend publishing integration.
- **Settings > Portfolio SEO** edits Home's overrides and the site-wide default
  sharing image/alternative text. Home does not depend on a WordPress Home page.
- Use the WordPress Media Library picker to select or remove images. Save the
  page/settings afterward. A 1200 by 630 image is recommended, not enforced.
- Empty strings mean no override. Image alt falls back to Media Library
  Alternative Text. No descriptions, credits, or other content are invented.
- Titles are plain text, at most 200 characters; descriptions and image alt are
  plain text, at most 500 characters. These are storage limits, not recommended
  search snippet lengths. Markup is stripped; non-string text input is cleared.

## Public Read Routes

`GET /wp-json/portfolio-studio/v1/settings` adds:

```json
{
  "seo": {
    "home": { "title": "", "description": "", "image": null },
    "defaultImage": null
  }
}
```

`GET /wp-json/wp/v2/pages?slug=about&_fields=slug,title,content,seo` and
`GET /wp-json/wp/v2/pages/<id>` add a read-only `seo` field:

```json
{
  "slug": "about",
  "seo": {
    "title": "Example Studio | About",
    "description": "An editor-written description of this page.",
    "image": {
      "id": 123,
      "url": "https://cms.example.com/wp-content/uploads/2026/11/sharing.jpg",
      "width": 1200,
      "height": 630,
      "alt": "An editor-written image description."
    }
  }
}
```

Examples are illustrative, not seeded portfolio content. The settings route is
anonymous/read-only and explicitly public. WordPress core controls page access:
anonymous page lists return published pages; unauthorized draft/private requests
are rejected. `seo` is additionally `null` for nonpublished or password-protected
pages, even in an authenticated edit response.

`seo` and `seo.home` are `{title: string, description: string, image: Image|null}`.
`seo.defaultImage` is `Image|null`. Image fields are `id` (positive integer), `url`
(HTTP(S) uploads URL), positive integer `width` and `height`, and `alt` (string).
Images must be local uploads, image attachments with dimensions, and public
(`inherit`/`publish`) without passwords. If attached to another post, that parent
must be published and not password-protected. Deleted, invalid, external, private,
or draft-attached images resolve to `null` on every read. Unresolved image IDs
and nonpublic image metadata are not exposed in the public SEO object.

The frontend should prefer page/Home overrides, then existing site-name and
description defaults; prefer the page/Home image, then `seo.defaultImage`.
No fallback values are merged into page SEO on the backend, so inheritance stays
explicit. Include `seo` in the frontend's `_fields` request and validate it.

## Writes and Permissions

Page meta keys are `_portfolio_seo_title` (string),
`_portfolio_seo_description` (string), `_portfolio_seo_image_id` (integer, minimum
0), and `_portfolio_seo_image_alt` (string). They are registered for Pages and
visible in REST `meta` only in authenticated `context=edit` responses.
`POST /wp-json/wp/v2/pages/<id>` can update them using the standard `meta` object;
WordPress authentication and `edit_post` capability are required. REST schema
checks reject wrong types, negative IDs, and oversized strings. Image selection
also runs the public-image validator. Use `0`/empty strings to clear overrides.

The page meta box requires its nonce, `edit_post`, and a nonrevision/nonautosave
request. Settings use the Settings API (`options.php`), its nonce, and
`manage_options`; the separate `portfolio_studio_seo_settings` option is not a
public write endpoint. Existing site settings and content are not migrated.

## Revalidation

Events are deduplicated and sent at WordPress shutdown, after metadata saves.
They use the existing `NEXT_PUBLIC_SITE_URL` and `REVALIDATION_SECRET` configuration
and authenticated `POST /api/revalidate` protocol; secrets stay server-side.

- Supported Page publish/update/unpublish and SEO meta edits send
  `{"type":"page","slug":"about"}` (using the affected slug).
- Home/default SEO settings add/update/delete send `{"type":"site_settings","slug":""}`.
- Selected image alt/file/dimensions edits, post changes/deletion, and parent
  visibility changes send the corresponding page/settings events.

No new frontend event types are introduced. The sender disables redirects, checks
TLS, and waits up to three seconds per event. Delivery is best-effort, without
automatic retries. Existing publishing hooks may also send their existing events.
If configuration is absent or invalid, no event is sent. No deployment, production
content update, or cache invalidation is performed by adding this code.

## Verification

Run PHP lint on `seo.php`, `portfolio-studio.php`, and `tests/seo-test.php`.
Run `tests/seo-test.php` with a WordPress PHPUnit test installation and the plugin
loaded before `init`; never use a production database. It covers defaults,
projected REST reads, text validation, public media filtering, write permissions,
nonce enforcement, editing controls, cache queues, and authenticated event payloads.
Run `node --check assets/seo-admin.js` for picker syntax and
`node --test tests/seo-admin.test.cjs` for picker selection/removal behavior,
from this plugin directory. The frontend handoff
must add metadata mapping and integration tests before this affects public SEO.
